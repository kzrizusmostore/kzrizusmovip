Belum punya token? Mulai dari Login & URL.

Cara dapat token, dari awal sampai siap
  1. Buka Login & URL, lalu pilih platform akunmu.
  2. Selesaikan login pada halaman Garena/platform di tab baru. Tunggu pengalihan selesai.
  3. Salin URL lengkap dari bilah alamat. Kembali ke sini dan tempel pada URL hasil login / EAT.
  4. Tekan Siapkan JWT. EAT diubah menjadi Access Token, lalu JWT. Tidak perlu menyalin hasil di tengah proses.
Sudah punya token?

Gunakan tab Access Token, JWT langsung, atau Akun Guest sesuai data yang tersedia. UID pemain saja bukan token login.

Login belum menghasilkan EAT?

URL yang masih memuat code= bukan EAT. Tunggu pengalihan selesai. Jika URL akhir tetap tidak memuat eat=, alur login ini belum menyediakan token yang diperlukan; jangan gunakan kode login sebagai penggantinya.

Bisa tempel token langsung atau JSON yang berisi access_token atau token_access. Token akan diubah menjadi JWT.

Kenapa token ditolak atau kedaluwarsa?
JWT punya masa berlaku jika memuat kolom exp. Siapkan token baru dari metode login yang sama. Pemeriksaan format di halaman ini bukan verifikasi keaslian token. Pastikan juga jam perangkat benar dan token berasal dari akun yang hendak diubah.
Bedanya API key, EAT, Access Token, dan JWT?
API key memberi aplikasi akses ke layanan penyedia. EAT ditukar menjadi Access Token. Access Token merupakan data login akun yang diterima layanan. JWT / BearerAuth adalah token yang dipakai untuk permintaan bio. Ketiganya tidak bisa saling menggantikan. API key sudah menggunakan konfigurasi aplikasi; kamu tidak perlu menempelkannya sebagai token.
Alur API & koneksi

API key memakai konfigurasi aplikasi. Nama kolom di tiap jalur berbeda; aplikasi menyesuaikannya otomatis.
